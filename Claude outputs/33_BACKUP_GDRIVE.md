# สำรองโปรเจกต์ SB Connect ขึ้น Google Drive

ไฟล์นี้จะถูกคัดลอกไปวางไว้ข้างๆ ตัวสำรองใน Drive ด้วย ชื่อ `RESTORE_GUIDE.md`
เพื่อให้ตอนกู้คืนไม่ต้องกลับมาหาในโปรเจกต์

---

## ทำอะไรได้

สั่งครั้งเดียว โปรเจกต์ทั้งก้อนจาก `D:\Projectsbconnect_app` จะไป**เขียนทับ**ของเดิมใน Google Drive
ให้ตรงกับสภาพในเครื่องเป๊ะทุกครั้ง **รวม `sql/` และ `.env` ซึ่ง git ไม่ยอมเก็บให้**

ถ้าเครื่องพัง GitHub จะมีทุกอย่างให้ยกเว้นสองอย่างนั้น ซึ่งเป็นสองอย่างที่สร้างใหม่ไม่ได้

```
วิธีใช้
  BACKUP_TO_GDRIVE.bat            เขียนทับของเดิม + เก็บ zip เล็กของ sql/.env
  BACKUP_TO_GDRIVE.bat /check     ลองดูก่อนว่าจะทำอะไร ไม่เขียนอะไรเลย
  BACKUP_TO_GDRIVE.bat /full      เก็บ zip ของโปรเจกต์ทั้งก้อนเพิ่มด้วย
  BACKUP_TO_GDRIVE.bat /nosnap    เขียนทับอย่างเดียว ไม่เก็บ zip อะไรเลย
  BACKUP_TO_GDRIVE.bat /yes       ข้ามการนับถอยหลังตอนรันครั้งแรก
```

---

## สิ่งที่จะได้ใน Drive

สคริปต์มองหาโฟลเดอร์ `SBconnection` ใน My Drive ให้เอง แล้วเขียนทับโฟลเดอร์ชื่อเดียวกับ
โปรเจกต์ในเครื่อง คือ `Projectsbconnect_app` — ที่เดิมของคุณพอดี ไม่ต้องตั้งค่าอะไร

```
My Drive\SBconnection\
  |
  +-- Projectsbconnect_app\        <- เขียนทับทุกครั้ง ตรงกับในเครื่องเป๊ะ
  |
  +-- _backup_snapshots\           <- zip เล็ก ๆ ของ sql + .env เก็บ 30 ชุด
  |     sql_env_2026-09-22_1530.zip
  |     sql_env_2026-09-21_0910.zip
  |
  +-- _backup_logs\                <- log ของแต่ละรอบ เก็บ 30 ไฟล์
  |     backup_2026-09-22_1530.log
  |
  +-- RESTORE_GUIDE.md             คู่มือฉบับนี้
```

**`Projectsbconnect_app\` เขียนทับแบบ mirror** คือลบทุกอย่างในนั้นที่ไม่มีในโปรเจกต์ด้วย
จะได้ไม่มีไฟล์เก่าค้างสะสม เป็นภาพสภาพล่าสุดจริง ๆ

> ⚠️ **ห้ามเอาไฟล์ของคุณไปวางในโฟลเดอร์นั้น** เพราะรอบสำรองถัดไปจะลบทิ้ง
> ถ้าต้องการเก็บอะไรไว้ ให้วางไว้นอกโฟลเดอร์นั้น

**รันครั้งแรก** สคริปต์จะบอกว่าในโฟลเดอร์มีกี่ไฟล์ที่จะถูกลบ แล้วนับถอยหลัง 10 วินาที
กด Ctrl+C หยุดได้ถ้าเปลี่ยนใจ หลังจากนั้นจะไม่ถามอีก เพราะมันจะวางไฟล์เครื่องหมาย
`.sbconnect_backup` ไว้ในโฟลเดอร์แล้ว (ห้ามลบไฟล์นี้)

## ทำไมยังเก็บ zip เล็ก ๆ ไว้ ทั้งที่สั่งเขียนทับ

เพราะ **โค้ดกับ `sql/` ได้รับการคุ้มครองไม่เท่ากัน**

| | ถ้าเขียนทับด้วยของเสีย |
|---|---|
| โค้ดใน `src/` | ย้อนได้ เพราะ `.git` ถูกสำรองไปด้วย และยังมีบน GitHub อีกชั้น |
| **`sql/` และ `.env`** | **ย้อนไม่ได้เลย** ไม่มีที่ไหนเก็บอีก |

zip ที่เก็บจึงมีแค่ `sql/` กับ `.env` เท่านั้น ขนาดไม่กี่ร้อย KB ต่อรอบ
เก็บ 30 ชุดล่าสุดก็ยังไม่ถึง 10 MB ไม่กิน Drive

ถ้าไม่อยากให้เก็บเลย สั่ง `BACKUP_TO_GDRIVE.bat /nosnap`

> **หมายเหตุ** ใน zip ไฟล์ `.env` ถูกเปลี่ยนชื่อเป็น `env.txt` เพราะ Windows ซ่อนไฟล์
> ที่ขึ้นต้นด้วยจุด ตอนกู้คืนให้เปลี่ยนชื่อกลับเป็น `.env`

## ⚠️ เรื่องความปลอดภัยที่ต้องระวัง

ตัวสำรองนี้มี **อีเมลและชื่อพนักงานจริงทั้งบริษัท 338 คน** อยู่ใน `sql/91_seed_from_xlsx`
และมี **รหัสกลางเข้าครั้งแรก** อยู่ใน `sql/19_` กับ `sql/21_` กับคีย์เชื่อมต่อใน `.env`

ดังนั้น

- โฟลเดอร์ `SBconnection` ใน Drive **ต้องเป็นส่วนตัวเสมอ**
- **ห้ามตั้งเป็น "ทุกคนที่มีลิงก์" (Anyone with the link) เด็ดขาด**
- ถ้าจะแชร์ให้คนอื่น ให้แชร์แบบระบุอีเมลรายคน และแชร์เฉพาะคนที่มีสิทธิ์เห็นข้อมูลพนักงานจริง
- ใช้บัญชี Google ของบริษัท ไม่ใช่บัญชีส่วนตัว

### ต้องเช็คก่อนสำรองรอบแรก

โฟลเดอร์ `SBconnection` ของคุณตอนนี้มีไอคอนรูปคนอยู่ข้างชื่อ และลิงก์ที่ส่งมาลงท้ายด้วย
`?usp=sharing` ซึ่งเป็นสัญญาณว่าเคยถูกแชร์ออกไป

**ก่อนรันสำรองรอบแรก ให้เปิดโฟลเดอร์ใน Drive กด Share แล้วดูว่า**

| ถ้าขึ้นว่า | ต้องทำ |
|---|---|
| **Restricted** | ใช้ได้ ไปต่อได้เลย |
| **Anyone with the link** | **เปลี่ยนเป็น Restricted ก่อน** ไม่งั้นใครที่มีลิงก์จะเห็นอีเมลพนักงานทั้งบริษัทและรหัสกลาง |

ลิงก์ที่เคยส่งออกไปแล้วจะใช้งานได้เรื่อยๆ จนกว่าจะเปลี่ยนค่านี้ การลบข้อความที่ส่งลิงก์ไปไม่ได้ทำให้ลิงก์ใช้ไม่ได้

## ต้องรอ Drive อัปโหลดให้เสร็จก่อนปิดเครื่อง

สคริปต์แค่ **เขียนไฟล์ลงโฟลเดอร์ Drive ในเครื่อง** ตัวโปรแกรม Google Drive for desktop
เป็นคนอัปโหลดขึ้นคลาวด์ต่อเองในเบื้องหลัง

**ดูไอคอน Drive ที่มุมขวาล่างจนขึ้นว่าอัปโหลดเสร็จแล้วก่อนปิดเครื่อง**
ถ้าปิดก่อน ไฟล์จะยังอยู่แค่ในเครื่อง ไม่ได้ขึ้นคลาวด์ = ไม่ได้สำรองจริง

## ถ้าหาโฟลเดอร์ Drive ไม่เจอ

สคริปต์จะไล่หาเองตามลำดับนี้

1. ตัวแปรระบบ `SB_GDRIVE`
2. ไฟล์ `backup_target.txt` ข้างๆ สคริปต์ (ใส่ path เต็มไว้บรรทัดแรก)
3. `%USERPROFILE%\My Drive`
4. `G:\My Drive` ไปจนถึง `Z:\My Drive`
5. `%USERPROFILE%\Google Drive` (Backup and Sync รุ่นเก่า)

ถ้ายังไม่เจอ ให้สร้างไฟล์ `backup_target.txt` ในโฟลเดอร์โปรเจกต์ แล้วใส่ path ของคุณบรรทัดแรก เช่น

```
G:\My Drive\SBconnection
```

## วิธีกู้คืนตอนเครื่องพัง

### กู้ทั้งโปรเจกต์

1. ลง Node.js รุ่นเดียวกับที่ใช้ (ดูในไฟล์ `.nvmrc` ของโปรเจกต์)
2. ก๊อป `My Drive\SBconnection\Projectsbconnect_app\` ทั้งโฟลเดอร์มาวางที่ `D:\Projectsbconnect_app`
3. เปิด cmd ในโฟลเดอร์นั้น แล้วสั่ง
   ```
   npm install
   npm run check
   npm run build
   ```
4. ตรวจว่า `.env` มาครบ ถ้าไม่มีให้ก๊อปจาก `.env.example` แล้วเติมค่าเอง

### กู้เฉพาะ sql ที่หาย

ก๊อปโฟลเดอร์ `Projectsbconnect_app\sql\` จาก Drive มาวางทับที่ `D:\Projectsbconnect_app\sql\`
ถ้าต้องการย้อนไปเวอร์ชันก่อนหน้า ให้แตก zip จาก `_backup_snapshots\` แทน
ไม่ต้อง build ใหม่ เพราะ `sql/` ไม่ได้ถูกรวมไปในตัวแอป

### กู้เฉพาะ .env

ก๊อป `Projectsbconnect_app\.env` จาก Drive มาวางที่รากโปรเจกต์
(หรือแตก `env.txt` จาก zip ใน `_backup_snapshots\` แล้วเปลี่ยนชื่อเป็น `.env`) แล้ว `npm run build` ใหม่
เพราะ Vite ฝังค่า `VITE_*` ตอน build ไม่ได้อ่านตอนรัน

> **หมายเหตุ** ตัวสำรองนี้ไม่ได้สำรอง **ฐานข้อมูล Supabase** กับ **ไฟล์ใน Google Drive ของแอป**
> (รูปโปรไฟล์ รูปข่าว หลักฐานภารกิจ) สองอย่างนั้นอยู่บนคลาวด์ของผู้ให้บริการ
> ถ้าต้องการสำรองฐานข้อมูลด้วย ใช้ปุ่ม Database Backups ในหน้า Supabase หรือบอกผมได้ ผมทำสคริปต์ dump ให้

## ทำให้สำรองเองอัตโนมัติ

### แบบที่ 1 สำรองทุกครั้งที่ดันขึ้น GitHub (ต่อไว้ให้แล้ว)

`push.bat` จะเรียก `BACKUP_TO_GDRIVE.bat` ให้เองหลังดันสำเร็จ
ถ้าสำรองไม่ผ่านจะแจ้งเตือนแต่ไม่ทำให้การดันล้ม

### แบบที่ 2 สำรองตามเวลาด้วย Task Scheduler

เปิด Task Scheduler แล้วสร้าง task ใหม่

| ช่อง | ใส่ |
|---|---|
| Program/script | `D:\Projectsbconnect_app\BACKUP_TO_GDRIVE.bat` |
| Add arguments | `/nosnap /yes` |
| Start in | `D:\Projectsbconnect_app` |
| Trigger | Daily 18:00 |

ใส่ `/nosnap` ในรอบรายวันเพื่อไม่ให้ Drive โตเร็วเกินไป ส่วน `push.bat` จะรันแบบเก็บ zip ให้เองตอนดันขึ้นจริง

> สคริปต์มี `pause` อยู่ท้ายไฟล์ ถ้าให้ Task Scheduler รัน หน้าต่างจะค้างรอกด Enter
> แก้ได้โดยตั้ง Add arguments เป็น `/nosnap /yes < nul` หรือลบบรรทัด `pause` ออก

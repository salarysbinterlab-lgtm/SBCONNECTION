## การรวมแผนก

ทำเป็น **ตารางแปลงชื่อที่แก้ได้** ชื่อ `roster_dept_map` อยู่ในไฟล์ `31_` ตอนต้น
แก้ตรงนั้นแล้วรันใหม่ได้เลย ไม่ต้องขอไฟล์จาก HR อีก

### ที่รวมให้แล้ว ตามที่คุณอธิบาย

| ชื่อในไฟล์ HR | รวมเป็น | จำนวนคน |
|---|---|---|
| `Logistic` + `Logistics` + `คลังสินค้าสำเร็จรูป` (FG) | **Logistics** | 13 + 8 + 8 = **29** |
| `ขาย` (SA) + `ส่งเสริมการขาย` + `การตลาดออนไลน์` (EC) | **ขายและการตลาด** | 18 + 9 + 5 = **32** |
| `ฝ่ายวิจัยและพัฒนา` + `วิจัยและพัฒนา` | **วิจัยและพัฒนา** (RD) | 7 + 2 = **9** |
| `บุคคล` + `ฝ่ายบุคคล` | **ฝ่ายบุคคล** (HR) | 9 + 4 = **13** |

27 แผนก → **21 แผนก**

> **QC** ในไฟล์นี้มีชื่อเดียวคือ `ควบคุมคุณภาพ` (20 คน) ไม่มี QCB QCR QCF QCM QA แยกมา
> ถ้าในระบบจริงมีแยก บอกได้ ผมเติมบรรทัดแปลงให้

### ยังไม่ได้รวม รอคุณยืนยัน

(เช่น `เจ้าหน้าที่ยกสินค้าสำเร็จรูปจัดส่ง` บอกได้ว่าเป็นฝั่ง FG)

### สิทธิ์หัวหน้าถูกย้ายตามให้ด้วย

นี่คือจุดที่พลาดง่ายที่สุด — สิทธิ์หัวหน้าผูกกับ**ชื่อแผนกเป็นข้อความ**
ถ้ารวม `Logistic` เข้า `Logistics` แล้วไม่ย้ายสิทธิ์ตาม **หัวหน้าคนนั้นจะไม่เห็นลูกทีมเลยสักคน**

`31_` ย้ายให้อัตโนมัติ และจัดการกรณีหัวหน้าคนเดียวถือสองแผนกที่รวมเป็นแผนกเดียวกัน
(ยุบเหลือแถวเดียว ไม่ให้ชน unique constraint) — ทดสอบกรณีนี้แล้ว

## สิ่งที่ไฟล์ 31_ ทำ และไม่ทำ

### ทำ

1. เพิ่มแผนกและตำแหน่งที่ยังไม่มีในระบบ
2. อัปเดตพนักงานเดิม — ชื่อ สกุล ชื่อเล่น คำนำหน้า แผนก ตำแหน่ง วันเริ่มงาน
3. เพิ่มพนักงานใหม่ (role = `user` เสมอ)
4. คนที่ไม่มีในไฟล์ใหม่ → ตั้งเป็น **`inactive`** และเพิกถอน session ที่ยังเปิดค้าง
5. คนที่เคย inactive แล้วกลับมามีในไฟล์ → เปิดใช้งานกลับ (ไม่แตะคนที่ถูก `suspended` ไว้โดยเจตนา)
6. เปิดรหัสกลางให้คนที่ยังไม่มีรหัสผ่าน เพื่อให้เข้าระบบครั้งแรกได้
7. เพิ่มคอลัมน์ `title_th` เก็บคำนำหน้าชื่อ (ของใหม่ ไม่กระทบอะไรเดิม)
8. บันทึกลง `admin_audit_logs` ว่าอัปเดตรายชื่อเมื่อไร กี่คน

### ไม่ทำเด็ดขาด

| ไม่แตะ | เพราะ |
|---|---|
| **ไม่ลบพนักงาน** ไม่ว่ากรณีใด | ลบแล้วแต้มและประวัติทั้งหมดหายตามไปด้วย (FK cascade) |
| **ไม่แตะอีเมล** | ไฟล์ HR ไม่มีคอลัมน์อีเมล ถ้าเขียนทับจะลบอีเมลเดิมทิ้งหมด |
| ไม่แตะแต้ม `points` `total_earned` | |
| ไม่แตะรูปโปรไฟล์ ประวัติเช็คอิน การแลกของ | |
| ไม่แตะ `role` | แอดมินยังเป็นแอดมิน หัวหน้ายังเป็นหัวหน้า |
| ไม่เปลี่ยนรหัสผ่านของคนที่ตั้งรหัสของตัวเองไปแล้ว | ใช้ `sb_open_first_login_for_all(true)` แตะเฉพาะคนที่ยังไม่มีรหัส |

## เรื่องที่ต้องตัดสินใจ

### 1. พนักงานใหม่ยังไม่มีอีเมล

ไฟล์ HR ไม่มีคอลัมน์อีเมล พนักงานใหม่จึงจะไม่มีอีเมลในระบบ

| ทำอะไรได้ | ทำไม่ได้ |
|---|---|
| เข้าสู่ระบบด้วยรหัสพนักงาน + รหัสกลาง ✅ | **ใช้ปุ่ม "ลืมรหัสผ่าน" ไม่ได้** เพราะระบบส่ง OTP ทางอีเมล |
| ใช้งานแอปได้ทุกอย่าง ✅ | |

ถ้าส่งไฟล์ที่มีคอลัมน์อีเมลมาเพิ่ม (รหัสพนักงาน + อีเมล แค่ 2 คอลัมน์ก็พอ) ผมทำไฟล์เติมอีเมลให้แยกได้ โดยไม่แตะอะไรอย่างอื่น

### 2. ตำแหน่งมีเลขต่อท้าย

มี 142 ตำแหน่ง เพราะบางตำแหน่งมีเลขสถานีต่อท้าย เช่น `พนักงานติดฉลากและบรรจุหีบห่อ 13` `... 11` `... 12` `... 5` `... 4`

ใช้งานได้ปกติ แค่ทำให้ตาราง `positions` ยาวกว่าที่ควร ถ้าอยากยุบให้เหลือชื่อเดียวแล้วเก็บเลขสถานีไว้คนละที่ก็บอกได้ แต่ไม่ใช่เรื่องด่วน

## วิธีตรวจ (ไม่ใช่การอ่านโค้ดเอา แต่รันจริง)

สร้างฐานข้อมูล PostgreSQL 16 ขึ้นมาใหม่จากไฟล์ `sql/` ของคุณทั้งชุด ตามลำดับติดตั้งจริง
(`01` → `16`, แล้ว `17`, `19`–`22`, `25`) ใช้พนักงานสมมติแทนไฟล์ `91_seed` ที่มีข้อมูลจริง
แล้วยิง RPC **ทุกตัวที่หน้าเว็บเรียกได้ (53 ตัว)** ในฐานะ role `anon` เหมือนที่ PostgREST ทำ
รวม **72 การทดสอบ** ครอบคลุมทั้งเส้นทางที่ควรผ่าน และเส้นทางที่ควรถูกปฏิเสธ

> ผลการติดตั้ง: ไฟล์ SQL ทั้ง 26 ไฟล์รันผ่าน **0 error** และ `18_VERIFY_SECURITY` ผ่านทุกข้อ

## 🔴 บั๊กที่เจอ — แก้แล้วในไฟล์ `sql/29_UI_FIELD_FIXES.sql`

### 1. แท็บ "Overall Activity Log" ฝั่งแอดมิน พังทั้งแท็บ
**อาการ** กดแล้วขึ้น "ระบบขัดข้องชั่วคราว" ทุกครั้ง ไม่เคยแสดงข้อมูลได้เลย

**สาเหตุ** `admin_list_overall_activity` มี `union all` 8 สาขา สาขาที่อ่านจาก `reward_redemptions`
เขียนว่า `select created_at` แต่ตารางนั้นใช้ชื่อคอลัมน์ว่า **`redeemed_at`**
PostgreSQL จึง throw `column "created_at" does not exist` ทำให้ฟังก์ชันล้มทั้งตัว

**แก้** เปลี่ยนเป็น `redeemed_at` และเพิ่ม `coalesce(completed_at, created_at)` ในสาขา `user_missions`
(ของเดิมภารกิจที่ยังรออนุมัติจะหายไปจากรายงาน เพราะ `completed_at` ยังเป็น null)

> ผลหลังแก้: คืนข้อมูล 29 แถวในฐานทดสอบ ทำงานปกติ

---

### 2. หน้าอันดับคะแนนฝั่งผู้ใช้ ไม่ขึ้นชื่อ ไม่ขึ้นแผนก ไม่ขึ้นรูป
**อาการ** ตารางอันดับแสดงเป็น **รหัสพนักงาน** แทนชื่อ · แผนกขึ้นเป็น **"-"** ทุกคน · รูปโปรไฟล์เป็นรูปสุ่มเสมอ

**สาเหตุ** เป็นบั๊กชนิดเดียวกับที่เคยแก้ฝั่งแอดมินไปแล้ว แต่**ฝั่งผู้ใช้ยังไม่ได้แก้**
ฐานข้อมูลส่ง `title` / `description` / `image_url` มา แต่หน้าเว็บอ่าน `full_name` / `department` / `avatar_url`

| ฐานข้อมูลส่ง | หน้าเว็บอ่าน | ผลลัพธ์เดิม |
|---|---|---|
| `title` = "สมชาย ใจดี" | `full_name` → `name` → `emp_id` | แสดง "001" |
| `description` = "บัญชี" | `department` → `dept` → `dept_th` | แสดง "-" |
| `image_url` | `avatar_url` → `avatar` | ใช้รูปสุ่มจาก dicebear |

**แก้** ให้ `list_ranking` ส่งกลับ **ทั้งสองชื่อ** (เพิ่ม `full_name`, `name`, `department`, `dept_th`,
`avatar_url`, `avatar`, `rank_no`, `nickname_th`, `pos_th`) ของเดิมยังอยู่ครบ ไม่ต้องแก้หน้าเว็บ

---

### 3. ปฏิทินหน้าแรก ไม่เคยขึ้นเครื่องหมายวันที่เช็คอิน
**อาการ** ปฏิทินเล็กในหน้าแรกไม่ไฮไลต์วันที่เคยเช็คอินเลยสักวัน แม้จะเช็คอินมาหลายวันแล้ว

**สาเหตุ** หน้าเว็บกรองด้วย `logsList.filter(l => l.source_type === 'CHECKIN')`
แต่ `list_my_overall_logs` **ไม่ได้ส่ง `source_type` มาเลย** — มันถูกเปลี่ยนชื่อไปเป็น `description`
ตัวกรองจึงได้ชุดว่างเปล่าทุกครั้ง

**แก้** เพิ่ม `source_type`, `amount`, `tx_type`, `checkin_date` เข้าไปในผลลัพธ์ (ของเดิมไม่หาย)

---

### 4. ปุ่มเช็คอินไม่เคยเปลี่ยนเป็น "เช็คอินแล้ว" + การ์ดสถิติหน้าแรกขึ้น 0 ตลอด
**อาการ**
- ปุ่มเช็คอินยังกดได้เรื่อยๆ แม้เช็คอินไปแล้ว กดแล้วเจอข้อความแจ้งว่าเช็คอินไปแล้ว แทนที่ปุ่มจะถูกปิดไปเลย
- การ์ด 3 ใบ "อ่านข่าวแล้ว / ภารกิจสำเร็จ / แลกของรางวัล" แสดง **0** เสมอ ไม่ว่าจะทำไปกี่ครั้ง

**สาเหตุ** หน้าเว็บอ่าน 4 ค่านี้จาก `get_home_dashboard` แต่ฐานข้อมูล**ไม่เคยส่งมาเลยสักตัว**
`checked_in_today`, `news_read_count`, `mission_done_count`, `reward_count`

**แก้** เพิ่มทั้ง 4 ค่า พร้อม `checkin_dates` (รายการวันที่เช็คอินย้อนหลัง 400 วัน) ให้ด้วย

### 5. แต้มพิเศษที่ HR แจก ไม่ถูกนับเข้า "แต้มสะสมทั้งหมด"
**อาการ** HR แจกแต้มพิเศษ 25 แต้ม → แต้มคงเหลือเพิ่มถูกต้อง แต่ `total_earned` ไม่ขยับ
ทดสอบจริง: แต้มคงเหลือ 36 แต่แต้มสะสมค้างอยู่ที่ 16 (ที่ถูกต้องคือ 41)

**สาเหตุ** `add_point_transaction` บวก `total_earned` เฉพาะเมื่อ `tx_type = 'earn'`
แต่ `admin_add_special_points` บันทึกเป็น `tx_type = 'adjust'` จึงตกหล่นทุกครั้ง
เจตนาเดิมคือไม่อยากนับ *refund* แต่เขียนกว้างเกินไปจนกินแต้มพิเศษไปด้วย

**แก้** เปลี่ยนเป็นนับ `earn` และ `adjust` ที่เป็นบวก (refund ยังไม่นับเหมือนเดิม)
แก้ทั้ง `add_point_transaction` และ `recalc_user_points` แล้วคำนวณย้อนหลังให้ทุกคนอัตโนมัติ
พร้อมแก้ `CHECK7` ใน `18_VERIFY_SECURITY.sql` ให้ใช้สูตรเดียวกัน ไม่งั้นจะรายงาน FAIL ผิดๆ

> ⚠️ หลังรันไฟล์ 29 ตัวเลข "แต้มสะสมทั้งหมด" ของพนักงานที่เคยได้แต้มพิเศษ **จะเพิ่มขึ้น** ซึ่งเป็นค่าที่ถูกต้อง
> แต้มคงเหลือไม่เปลี่ยน อันดับอาจสลับเล็กน้อยเพราะ `total_earned` เป็นตัวตัดสินอันดับรอง

## 🟡 ข้อสังเกต — ไม่ใช่บั๊ก แต่ควรรู้ไว้

### ก. `admin_save_manager_depts_batch` ลบทั้งตารางก่อนเขียนใหม่ทุกครั้ง
ฟังก์ชันนี้เริ่มด้วย `delete from manager_department_permissions;` แบบไม่มีเงื่อนไข
แล้วค่อยวนใส่ค่าใหม่ทีละแถว **และคืน `status: success` แม้จะใส่ไม่สำเร็จสักแถว**

หน้าเว็บส่ง payload ถูกต้องอยู่แล้ว (ทดสอบผ่าน) แต่ความเสี่ยงคือ
ถ้าแอดมินลาก-วางแผนกตอนที่รายการเดิมยังโหลดไม่เสร็จ (`moduleRows` ยังว่าง)
**สิทธิ์ของหัวหน้าทุกคนจะถูกล้างทิ้งทั้งตาราง** โดยหน้าจอขึ้นว่าบันทึกสำเร็จ

ข้อเสนอ: ให้ฟังก์ชันปฏิเสธถ้า `p_mappings` เป็น array ว่าง และคืนจำนวนแถวที่ลบ/เพิ่มมาให้ตรวจ
(ยังไม่ได้แก้ เพราะต้องคุยก่อนว่าอยากให้ "ลบหัวหน้าคนสุดท้ายออก" ทำได้หรือไม่)

### ข. ฟังก์ชันแอดมินบางตัวคืน `[]` แทนที่จะแจ้งว่าไม่มีสิทธิ์
`admin_list_users`, `admin_list_ledger` และกลุ่ม `admin_list_*` อื่นๆ เมื่อผู้ใช้ทั่วไปเรียก
จะคืน **array ว่าง** ไม่ใช่ error — **ข้อมูลไม่รั่ว ตรวจแล้วปลอดภัย**
แต่หน้าเว็บแยกไม่ออกระหว่าง "ไม่มีสิทธิ์" กับ "ไม่มีข้อมูล" ถ้าวันหลังมีปัญหาสิทธิ์จะดีบั๊กยาก

ส่วนตัวที่สำคัญจริง (`get_admin_dashboard`, `admin_upsert_user`, `admin_add_special_points`,
`admin_reset_password`, `admin_delete_user`, `admin_system_reset`) คืน error ชัดเจนถูกต้องแล้ว

### ค. `get_my_profile` คืนค่าว่างหลัง logout แทนที่จะคืน error
ตรวจแล้ว logout ทำงานถูกต้อง — `revoked_at` ถูกตั้ง, `validate_public_session` และ `daily_checkin`
คืน `SESSION_EXPIRED` ตามที่ควร แต่ `get_my_profile` คืน **null** เฉยๆ
ถ้าหน้าเว็บเผลออ่าน `.emp_id` จากค่า null จะเกิด error ในเบราว์เซอร์ ควรทำให้คืน error เหมือนตัวอื่น

## สิ่งที่ต้องทำต่อ

1. **รัน `sql/29_UI_FIELD_FIXES.sql` ใน Supabase SQL Editor** — ไฟล์เดียวจบ รันซ้ำได้ ไม่ลบข้อมูล
2. รัน `sql/18_VERIFY_SECURITY.sql` ซ้ำเพื่อยืนยัน (ผมแก้ CHECK7 ให้ใช้สูตรใหม่แล้ว)
3. ไม่ต้องแก้โค้ดหน้าเว็บเลย และ**ไม่ต้อง build ใหม่** เพราะแก้ที่ฐานข้อมูลล้วน
4. รีเฟรชหน้าเว็บแล้วตรวจด้วยตา 4 จุด:
   - แท็บ Overall Activity ฝั่งแอดมิน ต้องมีข้อมูลขึ้น
   - หน้าอันดับฝั่งผู้ใช้ ต้องขึ้นชื่อจริงและแผนก
   - ปุ่มเช็คอินหลังเช็คอินแล้ว ต้องเป็นสีเทาและกดไม่ได้
   - การ์ด "อ่านข่าวแล้ว / ภารกิจสำเร็จ / แลกของรางวัล" ต้องขึ้นตัวเลขจริง

## สิ่งที่ผมยืนยันไม่ได้จากที่นี่

1. **ข้อมูลจริงใน Supabase production** — ผมทดสอบบนฐานจำลองที่สร้างจากไฟล์ `sql/` ของคุณ
   ถ้า production เคยถูกแก้ด้วยมือนอกไฟล์เหล่านี้ อาจมีความต่าง
2. **การแสดงผลจริงบนเบราว์เซอร์** — ผมตรวจถึงระดับ "ฐานข้อมูลส่งฟิลด์นี้มาไหม" และ
   "หน้าเว็บอ่านฟิลด์ชื่อนี้" แต่ไม่ได้เปิดเว็บจริงดูด้วยตา (รัน `npm run dev` จากที่นี่ไม่ได้ npm ถูกบล็อก)
3. **การอัปโหลดไฟล์ผ่าน Apps Script** — ต้องทดสอบบนของจริง เพราะต้องมี Google Drive
4. **โมดูล Quotation** — ยังไม่ได้ตรวจรอบนี้ (คุณสั่ง hold ไว้) และมันไม่ได้เรียกผ่าน RPC ปกติ

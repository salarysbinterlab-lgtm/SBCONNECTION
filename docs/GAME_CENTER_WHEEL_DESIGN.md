## 1. เฟส A — แปลงระบบแต้มเป็นทศนิยม (ต้องทำก่อนเกม)

### ทำไมต้องแยกเฟส

แต้มในระบบเป็นจำนวนเต็มตลอดสาย และมีฟังก์ชันในฐานข้อมูลหลายสิบตัวที่คำนวณแต้ม
(เช็คอิน / อ่านข่าว / ภารกิจ / แลกของ / แต้มพิเศษจากแอดมิน / อันดับ / การ์ดพนักงาน)
เปลี่ยนแค่บางจุด = **ค่า 0.5 จะถูกปัดเศษเงียบๆ โดยไม่มี error** ซึ่งตรวจเจอยากมาก
จึงต้องไล่แก้ให้ครบในคราวเดียว แล้วทดสอบทั้งระบบก่อนไปต่อ

### ขั้นตอน

| ขั้น | ทำอะไร | ไฟล์ |
|---|---|---|
| A1 | **ตรวจก่อน** — รันสคริปต์อ่านอย่างเดียว ดูว่าในฐานข้อมูลจริงมีคอลัมน์/ฟังก์ชันไหนต้องแก้บ้าง แล้วส่งผลกลับมา | `sql/33_AUDIT_POINTS_TYPES.sql` ✅ เตรียมให้แล้ว |
| A2 | Backup ฐานข้อมูล (Supabase → Database → Backups) | — |
| A3 | รัน migration: เปลี่ยนคอลัมน์เป็น `numeric(12,2)` + สร้างฟังก์ชันที่เกี่ยวข้องใหม่ทั้งหมด | `sql/34_POINTS_DECIMAL_MIGRATION.sql` |
| A4 | แก้หน้าเว็บ: แสดงผลทศนิยม (12.5 ไม่ใช่ 12) และเปลี่ยน `parseInt` → `parseFloat` ตรงที่เกี่ยวกับแต้ม | `UserDashboard.tsx`, `AdminDashboard.tsx` |
| A5 | ทดสอบ: เช็คอิน / อ่านข่าว / ภารกิจ / แลกของตอนแต้มไม่พอ / แต้มพิเศษ / อันดับ / การ์ด / ประวัติ | — |

### คอลัมน์ที่จะแปลง (ยืนยันอีกครั้งหลังรัน A1)

`app_users.points`, `app_users.total_earned`,
`point_transactions.amount`, `point_transactions.balance_after`,
`overall_logs.point_before / points_change / point_after`,
`rewards.points_required`, `reward_redemptions.points_spent`,
`checkin_logs.points_earned`, แต้มของข่าว/ภารกิจ

### กติกาการปัดเศษ (ต้องตกลงให้ชัดตั้งแต่แรก)

- เก็บทศนิยม **2 ตำแหน่ง** (`numeric(12,2)`) — รองรับ 0.5 / 0.25 ได้
- แสดงผล: ถ้าเป็นจำนวนเต็มแสดง `12` ถ้ามีเศษแสดง `12.5` (ไม่โชว์ `12.50`)
- อันดับ/leaderboard เรียงตามค่าจริงรวมทศนิยม
- แลกของ: เทียบแต้มจริง เช่น มี 49.5 แลกของ 50 แต้มไม่ได้

### ความเสี่ยงที่ต้องรู้ก่อนกดรัน

- ควรรันตอนไม่มีคนใช้งาน (การเปลี่ยนชนิดคอลัมน์ล็อกตารางชั่วขณะ)
- ต้อง backup ก่อน — ถ้าผิดพลาดย้อนกลับได้
- ฟังก์ชันเก่าที่ยังคืนค่า integer ถ้าตกหล่นจะทำให้แต้มเพี้ยนแบบเงียบ ดังนั้น A1 สำคัญมาก ห้ามข้าม
- สคริปต์ A3 จะมีส่วนตรวจท้ายไฟล์ เทียบยอดรวมแต้มก่อน/หลังว่าต้องเท่ากันเป๊ะ

## 2. เฟส B — ตารางใหม่ของเกม (5 ตาราง prefix `game_`)

### 2.1 `game_wheels` — ตัวกงล้อ

| คอลัมน์ | ชนิด | ความหมาย |
|---|---|---|
| wheel_id | text pk | |
| name / description | text | ชื่อ + กติกาสั้นๆ ที่โชว์หน้าบ้าน |
| is_active | boolean | เปิดใช้งาน |
| allow_ticket | boolean | หมุนด้วยตั๋วได้ |
| allow_points | boolean | ซื้อสิทธิ์ด้วยแต้มได้ |
| spin_cost_points | numeric(12,2) | หมุน 1 ครั้งกี่แต้ม |
| daily_spin_limit | int | กี่ครั้ง/คน/วัน (0 = ไม่จำกัด) |
| start_at / end_at | timestamptz | ช่วงเวลาเปิด (null = ตลอด) |
| theme | jsonb | สีวง สีตัวชี้ รูปกลางวง |

### 2.2 `game_wheel_slots` — 6 ช่อง ← **โครงที่แอดมินแก้**

| คอลัมน์ | ชนิด | ความหมาย |
|---|---|---|
| slot_id | text pk | |
| wheel_id | text fk | |
| slot_index | int | **0–5 เท่านั้น** (บังคับด้วย check + unique คู่กับ wheel_id) |
| label | text | ข้อความในช่อง |
| image_url | text | รูป mini ในช่อง (อัปโหลดผ่าน Drive endpoint เดิม) |
| color | text | สีพื้นช่อง |
| prize_type | text | `coin` / `reward` / `ticket` / `none` |
| coin_amount | numeric(12,2) | ได้กี่ coin เช่น 0.5 |
| reward_id | text fk rewards | ของรางวัลชิ้นไหน |
| ticket_amount | int | ได้ตั๋วเพิ่มกี่ใบ |
| weight | int | อัตราออก |
| stock / stock_per_day | int | สต็อก (-1 = ไม่จำกัด) |
| is_active | boolean | |

**ช่องว่าง = ไม่ได้รางวัลอัตโนมัติ** — ถ้าแอดมินไม่ใส่ของในช่องไหน ระบบตั้ง `prize_type = 'none'`
แล้วหน้าบ้านแสดงรูปน้องกระต่ายร้องไห้ + ข้อความ "คุณไม่ได้รางวัล" ให้เอง ไม่ต้องตั้งค่าอะไรเพิ่ม

### 2.3 `game_tickets` — ตั๋วสะสม (ledger แบบเดียวกับ point_transactions)

`ticket_tx_id` · `emp_id` · `amount` (+1/-1) · `source_type` (`checkin` / `admin_grant` / `spin` / `wheel_prize`) · `source_id` · `balance_after` · `note` · `created_at`

เพิ่ม `app_users.wheel_tickets int default 0` เป็นยอดคงเหลือ (cache) — ตั๋วเป็นจำนวนเต็มเสมอ ไม่มีทศนิยม

**ตั๋วออกตอนเช็คอิน**: แก้ฟังก์ชันเช็คอินเดิม ให้แถมตั๋ว 1 ใบเมื่อเช็คอินสำเร็จ
กันซ้ำด้วย unique `(emp_id, source_type='checkin', วันที่)` — เช็คอินได้วันละครั้งอยู่แล้ว ตั๋วจึงได้วันละใบพอดี

### 2.4 `game_spins` — ประวัติการหมุน (audit)

`spin_id` · `wheel_id` · `emp_id` · `slot_id` · `slot_index` · `cost_type` (`ticket`/`points`/`free`/`test`) · `cost_amount` · `prize_type` · `prize_label` (snapshot) · `coin_awarded numeric(12,2)` · `reward_id` · `redemption_id` · `client_spin_id` **unique** · `is_test` · `played_date` (เวลาไทย) · `created_at`

### 2.5 `game_catalog` — รายการเกมในหน้า Game Center

`game_id` (`wheel` / `scratch` / `lucky_box` / `memory` / `whack` / `coin_catch`) · `name_th` · `name_en` · `icon` · `color` · `status` (`live` / `coming_soon` / `hidden`) · `sort_order`

แอดมินสลับเป็น live ได้เองตอนเกมถัดไปพร้อม โดยไม่ต้อง deploy

## 3. RPC ที่ต้องเพิ่ม

### หน้าบ้าน (ผู้เล่น)

| ฟังก์ชัน | คืนอะไร |
|---|---|
| `get_game_center(p_token)` | รายการเกม + สถานะ live/coming_soon |
| `get_wheel_state(p_token, p_wheel_id)` | ข้อมูลวง + 6 ช่อง (**label / รูป / สี เท่านั้น — ไม่มี weight ไม่มี stock**) + ตั๋วคงเหลือ + แต้ม + หมุนไปแล้วกี่ครั้งวันนี้ |
| `spin_wheel(p_token, p_wheel_id, p_cost_type, p_client_spin_id)` | `{ spin_id, slot_index, prize_type, prize_label, coin_awarded, reward_name, tickets_left, points_left }` |
| `list_my_spins(p_token, p_limit)` | ประวัติหมุนของตัวเอง |

**ลำดับใน `spin_wheel` (ทรานแซกชันเดียว)**

```
1. ตรวจ token → emp_id
2. client_spin_id ซ้ำ → คืนผลเดิม ไม่หมุนใหม่        ← กันกดซ้ำ/เน็ตหลุด
3. ล็อกแถวผู้ใช้ (SELECT ... FOR UPDATE)
4. ตรวจวงเปิดอยู่ / อยู่ในช่วงเวลา
5. ตรวจ daily_spin_limit จากวันที่ตามเวลาไทย (ฝั่ง DB)
6. หักตั๋ว หรือ หักแต้ม ตาม cost_type
7. เลือกช่องที่ active + สต็อกเหลือ → สุ่มตาม weight
8. ตัดสต็อกช่องนั้นในทรานแซกชันเดียวกัน
9. บันทึก game_spins
10. จ่ายรางวัล
      coin   → point_transactions + overall_logs + app_users.points
      ticket → game_tickets + app_users.wheel_tickets
      reward → reward_redemptions (Pending) เข้าคิวเดิมที่ HR อนุมัติ
      none   → ไม่จ่าย
11. คืน slot_index ให้หน้าบ้านหมุนไปหยุด
```

### หลังบ้าน (ตามแพทเทิร์น `admin_list_* / admin_upsert_* / admin_delete_*` ที่ระบบใช้อยู่)

| ฟังก์ชัน | ใช้ทำอะไร |
|---|---|
| `admin_list_wheels` / `admin_upsert_wheel` | ตั้งค่าตัวกงล้อ |
| `admin_list_wheel_slots(p_token, p_wheel_id)` | ดู 6 ช่อง **พร้อม weight / stock / % จริง** |
| `admin_upsert_wheel_slot` | แก้ช่อง (ชื่อ รูป สี รางวัล อัตรา สต็อก) |
| `admin_clear_wheel_slot` | ล้างช่องให้กลับเป็น "ไม่ได้รางวัล" |
| `admin_grant_tickets(p_token, p_emp_ids, p_amount, p_note)` | แจกตั๋วรายคน/ทั้งแผนก |
| `admin_test_spin(p_token, p_wheel_id, p_times)` | ทดลองหมุน 1 ครั้ง หรือจำลอง 1,000 ครั้งดูการกระจาย — ไม่แตะสต็อก/แต้ม |
| `admin_list_spins(p_token, ...)` | ประวัติหมุนทุกคน กรองตามวัน/คน/รางวัล |
| `admin_list_game_catalog` / `admin_upsert_game_catalog` | สลับเกมเป็น live / coming soon |

```
Game Center
┌──────────────┬──────────────┬──────────────┐
│ 🎡 กงล้อ      │ 🎫 บัตรขูด    │ 🎁 กล่องสุ่ม   │

├──────────────┼──────────────┼──────────────┤

│  เร็วๆ นี้     │  เร็วๆ นี้     │  เร็วๆ นี้      │
└──────────────┴──────────────┴──────────────┘
```

การ์ด coming soon เป็นสีเทา กดไม่ได้ มีป้าย "เร็วๆ นี้" มุมบน

**หน้ากงล้อ**
- วงล้อ 6 ช่องวาดด้วย Canvas — แต่ละช่องมีสี + ข้อความ + รูป mini
- แถบบน: 🎟 ตั๋วคงเหลือ · 🪙 coin คงเหลือ (รูปกระต่ายถือเหรียญ) · หมุนวันนี้ 1/3
- ปุ่มหมุนตามที่แอดมินเปิด: "ใช้ตั๋ว 1 ใบ" / "ใช้ 20 แต้ม"
- ไม่มีตั๋วและแต้มไม่พอ → ปุ่มเทา พร้อมข้อความ "เช็คอินวันนี้เพื่อรับตั๋ว"
- กดหมุน → เรียก RPC → ได้ `slot_index` → วงหมุน 5 รอบแล้วหยุดช่องนั้น (~4.5 วิ ช้าลงช่วงท้าย) → confetti → ป๊อปอัปรางวัล
- ถูกช่องว่าง → ป๊อปอัปรูปน้องกระต่ายร้องไห้ "คุณไม่ได้รางวัล ลองใหม่พรุ่งนี้นะ"
- ได้ของ → "ส่งเข้าคิวรับของแล้ว รอ HR อนุมัติ"
- ล่างสุด: ประวัติหมุน 10 ครั้งล่าสุดของตัวเอง

ผู้เล่นทำได้แค่หมุน ไม่มีปุ่มแก้ไขอะไร และหน้าเว็บไม่เคยรู้ weight/stock

## 5. หน้าตาฝั่งแอดมิน (โมดูลใหม่ "Game — กงล้อ")

```
┌─ ตั้งค่ากงล้อ ──────────────────┬─ ตัวอย่างสด ───────┐
│ ชื่อ  [กงล้อประจำเดือน      ]   │                    │
│ ☑ หมุนด้วยตั๋ว                  │      (วงล้อ 6 ช่อง  │
│ ☑ ซื้อสิทธิ์ด้วยแต้ม  [20] แต้ม  │     แสดงผลจริง      │
│ จำกัด/วัน [3]     เปิดใช้งาน ●   │    ตามที่ตั้งค่า)    │
├─ ช่องรางวัล (6 ช่องตายตัว) ─────┴────────────────────┤
│ # │ รูป │ ข้อความ    │ รางวัล       │น้ำหนัก│  %   │สต็อก│
│ 1 │ 🖼  │ 0.5 coin   │ coin 0.5    │  30  │30.0% │ ∞  │
│ 2 │ 🖼  │ 5 coin     │ coin 5      │  20  │20.0% │ ∞  │
│ 3 │ 🖼  │ เสื้อบริษัท │ ของ: เสื้อ   │   1  │ 1.0% │ 10 │
│ 4 │ 🖼  │ หมุนฟรี    │ ตั๋ว +1      │   9  │ 9.0% │ ∞  │
│ 5 │ 🐰  │ ไม่ได้รางวัล│ (ว่าง)       │  25  │25.0% │ ∞  │
│ 6 │ 🐰  │ ไม่ได้รางวัล│ (ว่าง)       │  15  │15.0% │ ∞  │
├──────────────────────────────────────────────────────┤
│ [ทดลองหมุน 1 ครั้ง]  [จำลอง 1,000 ครั้ง]  [แจกตั๋ว]    │
```

- % คำนวณสดจากน้ำหนัก ไม่ต้องคิดเอง
- "จำลอง 1,000 ครั้ง" โชว์ว่าแต่ละช่องออกกี่ครั้ง เทียบกับ % ที่ตั้ง — ใช้ตรวจก่อนเปิดจริง
- ช่องที่ไม่ใส่ของ = ไม่ได้รางวัล โชว์รูปกระต่ายร้องไห้อัตโนมัติ
- แท็บย่อย: ประวัติการหมุนทั้งหมด (กรอง/ส่งออก) · แจกตั๋ว

## 6. ความปลอดภัย / ความถูกต้อง

| เรื่อง | วิธีจัดการ |
|---|---|
| หน้าเว็บโกงผลรางวัล | DB สุ่มทั้งหมด หน้าเว็บได้แค่ `slot_index` |
| weight/stock รั่ว | ไม่ส่งผ่าน RPC ผู้เล่น + ปิด RLS ไม่ให้ anon อ่านตาราง slots ตรงทาง REST |
| กดซ้ำ/เน็ตหลุด | `client_spin_id` unique — ยิงซ้ำได้ผลเดิม ไม่หักซ้ำ |
| แย่งรางวัลชิ้นสุดท้าย | ตัดสต็อกในทรานแซกชันเดียวกับการสุ่ม + ล็อกแถว |
| เปลี่ยนนาฬิกามือถือ | นับ daily limit จากวันที่ฝั่ง DB (เวลาไทย) |
| ของรางวัลจริง | เข้าคิว `reward_redemptions` Pending — HR อนุมัติด้วยหน้าจอเดิม |
| ข้อมูลเพี้ยนจากการทดสอบ | `is_test = true` ตัดออกจากสถิติ ไม่จ่ายจริง |
| แต้มปัดเศษเงียบ | เฟส A ต้องเสร็จและทดสอบผ่านก่อนเริ่มเฟส B |
| ก่อนเปิดใช้จริง | ให้ HR ดูกติกาและมูลค่ารางวัล + แปะประกาศกติกาในแอป |

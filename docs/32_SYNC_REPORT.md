# ผลตรวจการซิงค์ ฝั่ง admin ↔ ฝั่ง user
**แอปสะสมแต้ม: เช็คอิน · ภารกิจ · สะสมแต้ม · แลกของรางวัล · 21 กันยายน 2569**

---

## วิธีตรวจ

ไม่ได้ดูจากโค้ด แต่**เดินวงจรจริงบนฐานข้อมูล PostgreSQL 16** ที่สร้างจากไฟล์ `sql/` ของคุณทั้งชุด
แล้วสลับบทบาทไปมาระหว่าง admin กับ user เหมือนใช้งานจริง

```
admin เพิ่ม  →  user เห็น  →  user ทำ  →  admin เห็น  →  แต้มเข้า  →  อันดับขยับ  →  admin ตรวจย้อนได้
```

รวม **51 ข้อ ผ่านทั้งหมด 51 ข้อ**

| หมวด | ผล |
|---|---|
| เช็คอิน | 4/4 ผ่าน |
| ข่าว | 6/6 ผ่าน |
| ภารกิจ (ต้องอนุมัติ) | 6/6 ผ่าน |
| ภารกิจ (ได้แต้มทันที) | 1/1 ผ่าน |
| ภารกิจ (ไม่อนุมัติ) | 2/2 ผ่าน |
| ของรางวัล | 10/10 ผ่าน |
| แต้มพิเศษจาก HR | 4/4 ผ่าน |
| อันดับ | 5/5 ผ่าน |
| ความถูกต้องของแต้ม | 3/3 ผ่าน |
| แจ้งเตือน | 3/3 ผ่าน |
| หน้าแรก | 4/4 ผ่าน |
| มุมมองแอดมิน | 3/3 ผ่าน |

> ⚠️ ผลนี้เป็นของฐานข้อมูล**หลังรัน `sql/29_UI_FIELD_FIXES.sql` แล้ว**
> ถ้ายังไม่รันไฟล์นั้น หมวดอันดับ / หน้าแรก / มุมมองแอดมิน จะยังตกอยู่

## วงจรหลักที่เดินจริงแล้วผ่าน

### เช็คอิน
- กดเช็คอิน → แต้มเพิ่มจริง
- กดซ้ำวันเดียวกัน → ไม่ได้แต้มอีก ระบบตอบ "เช็คอินวันนี้แล้ว"
- หน้าแรกรู้ว่าวันนี้เช็คอินแล้ว (ปุ่มจะเป็นสีเทากดไม่ได้)
- ปฏิทินได้รับรายการวันที่เช็คอินย้อนหลัง

### ข่าว
- admin เพิ่มข่าว → user เห็นทันที
- อ่านข่าว → ได้แต้มตรงตามที่ admin ตั้งไว้ (ตั้ง 7 ได้ 7)
- อ่านซ้ำวันเดียวกัน → ไม่ได้แต้มอีก
- ข่าวที่อ่านแล้วถูกทำเครื่องหมาย "อ่านแล้ว" ให้ผู้ใช้
- admin ปิดข่าว → หายจากฝั่ง user ทันที

### ภารกิจ
| กรณี | ผลที่ได้ |
|---|---|
| admin เพิ่มภารกิจ | user เห็นทันที |
| ภารกิจที่ต้องอนุมัติ: user ส่ง | **ยังไม่ได้แต้ม** รอ admin ตรวจ |
| admin เห็นงานที่ส่งเข้ามา | เห็นทันที สถานะ Pending |
| admin กดอนุมัติ | user ได้แต้มครบตามที่ตั้ง (20) |
| user ส่งภารกิจเดิมซ้ำ | ถูกกัน "ส่งภารกิจนี้แล้ว" ไม่ได้แต้มซ้ำ |
| ภารกิจที่ไม่ต้องอนุมัติ | ได้แต้มทันทีที่กด (8) |
| admin กดไม่อนุมัติ | user ไม่ได้แต้ม สถานะเป็น Rejected ทั้งสองฝั่ง |

### ของรางวัล
| กรณี | ผลที่ได้ |
|---|---|
| admin เพิ่มของรางวัล | user เห็นทันที |
| user แลก | แต้มถูกหักถูกต้อง (10) |
| สต็อก | ลดจาก 2 เหลือ 1 อัตโนมัติ |
| admin เห็นรายการแลก | เห็นทันที สถานะ Pending |
| admin กดจ่ายของแล้ว | user เห็นสถานะเปลี่ยนเป็น Approved |
| แต้มไม่พอ | ปุ่มแลกปิด (`can_redeem=false`) และถ้าฝืนแลกก็ถูกปฏิเสธ **แต้มไม่ติดลบ** |
| ของหมดสต็อก | แลกไม่ได้ ระบบตอบ "ของรางวัลหมดแล้ว" |
| admin ปิดของรางวัล | หายจากฝั่ง user ทันที |

### แต้มพิเศษจาก HR
- แจก 30 แต้ม → แต้มคงเหลือเพิ่ม 30 **และแต้มสะสมทั้งหมดเพิ่ม 30 ด้วย** (บั๊กที่แก้ไปในไฟล์ 29)
- admin เห็นประวัติการแจก
- user เห็นรายการนี้ในประวัติของตัวเอง

### อันดับ
- ลำดับตรงกับแต้มจริงในฐานข้อมูลเป๊ะ
- แสดง**ชื่อจริง**และ**แผนก** ไม่ใช่รหัสพนักงาน (บั๊กที่แก้ไปในไฟล์ 29)
- แต้มในหน้าอันดับตรงกับแต้มจริงของผู้ใช้
- อันดับฝั่ง admin กับฝั่ง user เรียงตรงกัน

### ความถูกต้องของแต้ม (ตรวจทุกคนในระบบ)
- แต้มคงเหลือของทุกคน = ผลรวมในสมุดแต้ม ✅ ตรงทั้งหมด
- แต้มสะสมของทุกคน = ผลรวมรายการที่ได้แต้มจริง ✅ ตรงทั้งหมด
- ไม่มีใครแต้มติดลบ ✅

### แจ้งเตือน / หน้าแรก / มุมมองแอดมิน
- user ได้รับแจ้งเตือนจากกิจกรรมที่เกิดขึ้นจริง กดอ่านแล้วสถานะเปลี่ยน ตัวนับที่ยังไม่อ่านทำงาน
- แต้มและตัวนับทั้ง 3 ตัวบนหน้าแรกตรงกับข้อมูลจริงในฐานข้อมูลทุกตัว
- สมุดแต้มฝั่ง admin เห็นครบทุกรายการ
- กิจกรรมรวมทั้งระบบครอบคลุมครบทุกหมวด: แต้ม · เช็คอิน · ข่าว · ภารกิจ · ของรางวัล · แอดมิน · เข้าสู่ระบบ

## 🔧 สิ่งที่แก้เพิ่มรอบนี้ — หน้าจอค้างข้อมูลเก่า

**ปัญหาที่เจอ (ไม่ใช่เรื่องฐานข้อมูล แต่เป็นเรื่องหน้าเว็บ)**

หน้าเว็บดึงข้อมูลใหม่**เฉพาะตอนสลับแท็บเท่านั้น** ผลคือ

- ผู้ใช้เปิดแอปค้างไว้ที่หน้าแรก แอดมินเพิ่มข่าว/ภารกิจ/ของรางวัลระหว่างนั้น → **ผู้ใช้ไม่เห็นจนกว่าจะสลับแท็บหรือรีเฟรช**
- แอดมินนั่งอยู่หน้า "ภารกิจที่ส่งเข้ามา" มีคนส่งงานเข้ามาใหม่ → **แอดมินไม่เห็นจนกว่าจะสลับเมนู**

**สิ่งที่ทำ** เพิ่มการดึงข้อมูลใหม่อัตโนมัติเมื่อกลับเข้าแอป ทั้งสองฝั่ง

- สลับแอปบนมือถือแล้วกลับมา → ดึงใหม่
- สลับแท็บเบราว์เซอร์แล้วกลับมา → ดึงใหม่
- เว้นระยะอย่างน้อย 20 วินาที กันยิงรัวตอนสลับหน้าต่างถี่ ๆ
- ถอด listener ตอนออกจากหน้าจอ ไม่มี memory leak

## สิ่งที่ผมยืนยันไม่ได้จากที่นี่

1. ผมทดสอบบนฐานข้อมูลจำลองที่สร้างจากไฟล์ `sql/` ของคุณ ไม่ใช่ Supabase production ตัวจริง
   ถ้า production เคยถูกแก้ด้วยมือนอกไฟล์เหล่านี้ อาจมีความต่าง
2. ไม่ได้เปิดเว็บจริงดูด้วยตา (รัน `npm run dev` จากที่นี่ไม่ได้ เพราะ npm ถูกบล็อก)
   ตรวจถึงระดับ "ฐานข้อมูลส่งค่านี้มา" และ "หน้าเว็บอ่านชื่อนี้" เท่านั้น
3. การอัปโหลดรูปผ่าน Google Apps Script ต้องทดสอบบนของจริง

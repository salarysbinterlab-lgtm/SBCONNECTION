# สำรองโปรเจกต์ SB Connect ขึ้น Google Drive

ไฟล์นี้จะถูกคัดลอกไปวางไว้ข้างๆ ตัวสำรองใน Drive ด้วย ชื่อ `RESTORE_GUIDE.md`
เพื่อให้ตอนกู้คืนไม่ต้องกลับมาหาในโปรเจกต์

**ปรับปรุงครั้งล่าสุด 23 กันยายน 2569 — กฎเปลี่ยนไป 2 ข้อ อ่านหัวข้อถัดไปก่อน**

---

## ⚠️ สองกฎที่เปลี่ยนไป และทำไมถึงเปลี่ยน

### กฎที่ 1 — เพิ่มและทับเท่านั้น ไม่ลบอะไรใน Drive อีกแล้ว

เดิมสคริปต์ใช้ `robocopy /MIR` ซึ่งแปลว่า *"ทำให้ปลายทางเหมือนต้นทางเป๊ะ"* —
**ลบทุกอย่างใน Drive ที่ไม่มีในเครื่อง**

สิ่งที่เกิดขึ้นจริง: โปรเจกต์ Apps Script ถูกเก็บไว้ในโฟลเดอร์ Drive นั้นในรูปไฟล์
`SBconnect_app.gscript` ซึ่งเป็นไฟล์ที่ **อยู่บนคลาวด์อย่างเดียว ไม่มีตัวจริงในเครื่อง**
รอบสำรองถัดมา `/MIR` จึงมองว่าเป็น "ไฟล์แปลกปลอม" แล้วลบทิ้ง
= **โปรเจกต์ Apps Script ทั้งตัวลงถังขยะ Drive** พร้อม Script Properties ทั้งหมด

> หลักฐาน: ไฟล์ที่กู้กลับมามีวันที่แก้ไขล่าสุด 15 ก.ย. แต่รอบสำรองล่าสุดคือ 22 ก.ย.
> ถ้าไฟล์อยู่ใน Drive ตลอด มันต้องถูกลบไปตั้งแต่รอบวันที่ 22 แล้ว

ตอนนี้สคริปต์ใช้ `/E` แทน **ไม่มี `/MIR` ไม่มี `/PURGE`** และมีคอมเมนต์เตือนไว้ในไฟล์ว่าห้ามเอากลับมา
พร้อมกันนั้นไฟล์ชนิด Google (`*.gscript` `*.gsheet` `*.gdoc` `*.gform` ฯลฯ) และ `desktop.ini`
ถูกใส่ใน `/XF` เป็นด่านที่สอง

**ราคาที่ต้องจ่าย:** ไฟล์ที่คุณลบออกจากเครื่องจะค้างอยู่ใน Drive ตลอดไป
ต้องเข้าไปลบเองเป็นครั้งคราว ไม่งั้น Drive จะสะสมของเก่าที่เลิกใช้แล้ว

### กฎที่ 2 — ข้อมูลบริษัทไม่ออกจากเครื่อง

`sql/` กับ `apps_script/` **ไม่ถูกสำรองขึ้น Drive อีกต่อไป** และทุกครั้งที่รัน
สคริปต์จะ **ลบทิ้งจาก Drive** ถ้าพบว่ารอบเก่าเคยส่งขึ้นไป พร้อมกับ zip เก่าชื่อ `sql_env_*.zip`

zip สำรองของสองโฟลเดอร์นี้ย้ายมาอยู่ในเครื่องแทน ที่
`D:\Projectsbconnect_app\_local_snapshots\private_<วันเวลา>.zip`

## ทำอะไรได้

สั่งครั้งเดียว โปรเจกต์จาก `D:\Projectsbconnect_app` จะถูก**คัดลอกและเขียนทับ**ขึ้น Google Drive
ยกเว้นของที่สร้างใหม่ได้ กับข้อมูลบริษัทตามกฎที่ 2

```
วิธีใช้
  BACKUP_TO_GDRIVE.bat            คัดลอกขึ้น Drive + เก็บ zip ในเครื่อง
  BACKUP_TO_GDRIVE.bat /check     ลองดูก่อนว่าจะทำอะไร ไม่เขียนอะไรเลย
  BACKUP_TO_GDRIVE.bat /full      เก็บ zip ของโปรเจกต์ทั้งก้อนเพิ่มด้วย
  BACKUP_TO_GDRIVE.bat /nosnap    คัดลอกอย่างเดียว ไม่เก็บ zip อะไรเลย
  BACKUP_TO_GDRIVE.bat /yes       ไม่ถามอะไร ใช้ตอนถูกเรียกจาก push.bat
```

**รัน `/check` ก่อนเสมอถ้าไม่ได้รันมานาน** จะได้เห็นว่ามันจะแตะอะไรบ้าง

## สิ่งที่จะได้ใน Drive

สคริปต์มองหาโฟลเดอร์ `SBconnection` ใน My Drive ให้เอง แล้วเขียนลงโฟลเดอร์ชื่อเดียวกับ
โปรเจกต์ในเครื่อง คือ `Projectsbconnect_app`

```
My Drive\SBconnection\
  |
  +-- Projectsbconnect_app\        <- คัดลอกและทับ ไม่มีการลบ
  |     (ไม่มี sql\ และไม่มี apps_script\ โดยตั้งใจ)
  |
  +-- _backup_logs\                <- log ของแต่ละรอบ เก็บ 30 ไฟล์
  |     backup_2026-09-23_0910.log
  |
  +-- RESTORE_GUIDE.md             คู่มือฉบับนี้
  |
  +-- SBconnect_app.gscript        <- โปรเจกต์ Apps Script (แนะนำให้ย้ายมาไว้ชั้นนี้)

D:\Projectsbconnect_app\
  +-- _local_snapshots\            <- zip ของ sql + apps_script + .env เก็บ 30 ชุด
        private_2026-09-23_0910.zip
        private_2026-09-22_1530.zip
```

> **ที่เก็บโปรเจกต์ Apps Script** ควรอยู่ที่ `SBconnection` ชั้นนอก **ไม่ใช่** ใน
> `Projectsbconnect_app` แม้ตอนนี้สคริปต์จะไม่ลบแล้วก็ตาม — อย่าเก็บไฟล์ที่มีอยู่บนคลาวด์
> อย่างเดียวไว้ในโฟลเดอร์ที่มีตัว sync คอยเขียนทับ

## สำเนาของแต่ละอย่างอยู่ที่ไหนบ้าง

ตารางนี้คือสิ่งที่ต้องดูตอนเครื่องพัง

| | ในเครื่อง | Drive | GitHub |
|---|:---:|:---:|:---:|
| `src/` `public/` `docs/` | ✅ | ✅ | ✅ |
| `apps_script/` | ✅ | ❌ | ✅ |
| `.env` | ✅ | ✅ | ❌ |
| **`sql/`** | ✅ | ❌ | ❌ |
| `_local_snapshots\private_*.zip` (sql + apps_script + .env) | ✅ | ❌ | ❌ |

**`sql/` มีสำเนาอยู่ในเครื่องเดียวเท่านั้น** ทั้ง Drive และ GitHub ไม่มี
→ **ก๊อป `private_*.zip` ล่าสุดลง USB หรือที่อื่นเป็นระยะ** นี่คือจุดอ่อนที่เหลืออยู่จุดเดียวของระบบสำรองชุดนี้

## ⚠️ เรื่องความปลอดภัย

หลังเปลี่ยนกฎที่ 2 แล้ว **ตัวสำรองใน Drive ไม่มีข้อมูลส่วนบุคคลของพนักงานและไม่มีรหัสกลางอีกแล้ว**
สิ่งที่ยังมีคือ `.env` (ค่าเปิดเผยได้) และ `.git` (ประวัติโค้ด)

ถึงอย่างนั้นก็ยังควรทำตามนี้

- โฟลเดอร์ `SBconnection` ใน Drive **ต้องเป็น Restricted**
- **ห้ามตั้งเป็น "ทุกคนที่มีลิงก์" (Anyone with the link)**
- ถ้าจะแชร์ ให้แชร์แบบระบุอีเมลรายคน
- ใช้บัญชี Google ของบริษัท ไม่ใช่บัญชีส่วนตัว

> การปิดแชร์โฟลเดอร์**ไม่ทำให้รูปในแอปหาย** เพราะแอปแสดงรูปจาก *รหัสไฟล์*
> (`lh3.googleusercontent.com/d/<fileId>`) และไฟล์แต่ละใบถูกตั้งสิทธิ์
> "ใครมีลิงก์ก็ดูได้" ไว้ที่ตัวไฟล์เองตอนอัปโหลด ไม่ได้อาศัยสิทธิ์ของโฟลเดอร์
> ถ้าไม่แน่ใจ ให้รัน `IMAGE_SHARING_CHECK()` ใน Apps Script ให้ได้ผลเป็น 0 ก่อน

## ต้องรอ Drive อัปโหลดให้เสร็จก่อนปิดเครื่อง

สคริปต์แค่ **เขียนไฟล์ลงโฟลเดอร์ Drive ในเครื่อง** ตัวโปรแกรม Google Drive for desktop
เป็นคนอัปโหลดขึ้นคลาวด์ต่อเองในเบื้องหลัง

**ดูไอคอน Drive ที่มุมขวาล่างจนขึ้นว่าอัปโหลดเสร็จแล้วก่อนปิดเครื่อง**
ถ้าปิดก่อน ไฟล์จะยังอยู่แค่ในเครื่อง ไม่ได้ขึ้นคลาวด์ = ไม่ได้สำรองจริง

## ถ้าหาโฟลเดอร์ Drive ไม่เจอ

สคริปต์จะไล่หาเองตามลำดับนี้

1. ตัวแปรระบบ `SB_GDRIVE`
2. ไฟล์ `backup_target.txt` ข้างๆ สคริปต์ (ใส่ path เต็มไว้บรรทัดแรก)
3. `%USERPROFILE%\My Drive`
4. `G:\My Drive` ไปจนถึง `Z:\My Drive`
5. `%USERPROFILE%\Google Drive` (Backup and Sync รุ่นเก่า)

ถ้ายังไม่เจอ ให้สร้างไฟล์ `backup_target.txt` ในโฟลเดอร์โปรเจกต์ แล้วใส่ path บรรทัดแรก เช่น

```
G:\My Drive\SBconnection
```

## วิธีกู้คืนตอนเครื่องพัง

### กู้ทั้งโปรเจกต์

1. ลง Node.js รุ่นเดียวกับที่ใช้ (ดูในไฟล์ `.nvmrc`)
2. ก๊อป `My Drive\SBconnection\Projectsbconnect_app\` ทั้งโฟลเดอร์มาวางที่ `D:\Projectsbconnect_app`
3. **เติมของที่ไม่ได้อยู่ใน Drive กลับเข้าไป**
   - `apps_script/` — `git checkout` จาก GitHub ได้เลย หรือแตกจาก `private_*.zip`
   - `sql/` — **แตกจาก `private_*.zip` เท่านั้น ไม่มีที่อื่น** ถ้าไม่มี zip = ต้องสร้างใหม่ทั้งหมด
4. เปิด cmd ในโฟลเดอร์นั้น แล้วสั่ง
   ```
   npm install
   npm run check
   npm run build
   ```
5. ตรวจว่า `.env` มาครบ ถ้าไม่มีให้ก๊อปจาก `.env.example` แล้วเติมค่าเอง
   (ค่า `VITE_*` ทั้ง 3 ตัวหาได้จาก GitHub > Settings > Secrets and variables > Actions > Variables)

### กู้เฉพาะ sql ที่หาย

แตก `sql\` จาก `_local_snapshots\private_<วันเวลา>.zip` ในเครื่อง มาวางทับที่ `D:\Projectsbconnect_app\sql\`
ไม่ต้อง build ใหม่ เพราะ `sql/` ไม่ได้ถูกรวมไปในตัวแอป

### กู้เฉพาะ .env

ก๊อป `Projectsbconnect_app\.env` จาก Drive มาวางที่รากโปรเจกต์
(หรือแตก `env.txt` จาก `private_*.zip` แล้วเปลี่ยนชื่อเป็น `.env`) แล้ว `npm run build` ใหม่
เพราะ Vite ฝังค่า `VITE_*` ตอน build ไม่ได้อ่านตอนรัน

### กู้โปรเจกต์ Apps Script ที่ถูกลบ

Google Drive เก็บของในถังขยะ **30 วัน** → drive.google.com > ถังขยะ > หาไฟล์ `.gscript` >
คลิกขวา > กู้คืน กลับมาครบทั้งโค้ด Script Properties และ deployment เดิม (URL `/exec` ไม่เปลี่ยน)

> **หมายเหตุ** ตัวสำรองนี้ไม่ได้สำรอง **ฐานข้อมูล Supabase** กับ **ไฟล์รูปใน Google Drive ของแอป**
> (รูปโปรไฟล์ รูปข่าว รูปของรางวัล หลักฐานภารกิจ รูปเกม) สองอย่างนั้นอยู่บนคลาวด์ของผู้ให้บริการ
> ฐานข้อมูลใช้ปุ่ม Database Backups ในหน้า Supabase

## ทำให้สำรองเองอัตโนมัติ

### แบบที่ 1 สำรองทุกครั้งที่ดันขึ้น GitHub (ต่อไว้ให้แล้ว)

`push.bat` จะเรียก `BACKUP_TO_GDRIVE.bat /yes` ให้เองหลังดันสำเร็จ
ถ้าสำรองไม่ผ่านจะแจ้งเตือนแต่ไม่ทำให้การดันล้ม

### แบบที่ 2 สำรองตามเวลาด้วย Task Scheduler

เปิด Task Scheduler แล้วสร้าง task ใหม่

| ช่อง | ใส่ |
|---|---|
| Program/script | `D:\Projectsbconnect_app\BACKUP_TO_GDRIVE.bat` |
| Add arguments | `/nosnap /yes` |
| Start in | `D:\Projectsbconnect_app` |
| Trigger | Daily 18:00 |

> ใส่ `/nosnap` เพราะ zip ควรเก็บตอนที่แก้ `sql/` จริงๆ ไม่ใช่ทุกวัน
> ถ้าอยากได้ zip รายวันด้วยก็เอา `/nosnap` ออก
